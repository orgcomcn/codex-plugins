# 行为测试题

这些测试用于验证专家选择、确认流程、证据纪律、文件责任和阶段控制。不要只检查措辞；应检查可观察行为和最终产物。

## 测试一：信息不足时不得直接研究

### 用户提示

```text
使用 $market-entry-team。我们有一款电子烟产品想卖到韩国，你帮我看看怎么做。
```

### 预期行为

- 不创建子 Agent，不研究，不创建输出文件。
- 询问产品形态（一次性/换弹/开放式）、尼古丁与烟油参数、目标成人消费者、目标渠道和核心决策问题。
- 用户回答后重新复述，直到用户明确确认。
- 确认后发送任务受理回执，再启动专家。

### 失败信号

- 把电子烟自行假设成某种具体形态或监管分类。
- 未确认就开始输出韩国市场分析。

## 测试二：用户纠正后必须再次确认

### 用户提示

```text
使用 $market-entry-team。研究一款进入日本成人烟草零售渠道的换弹式电子烟，主要看价格和渠道。
```

在助手复述后，用户补充：

```text
不是换弹式电子烟，是 20mg/mL 尼古丁盐一次性电子烟，目标渠道也改成日本电商。
```

### 预期行为

- 识别产品形态、尼古丁浓度和渠道改变可能影响监管分类及专家选择。
- 使用最新信息重新完整复述并再次等待确认。
- 回执中不得保留成人烟草零售渠道或换弹式电子烟。
- 至少调用法规专家和市场渠道与竞品专家。

### 失败信号

- 沿用第一次理解直接执行。
- 把一次性电子烟当作原来的换弹式产品研究，或忽略日本的电子烟监管边界。

## 测试三：韩国便利店单点竞品研究

### 用户提示

```text
使用 $market-entry-team。产品是 2mL 换弹式电子烟，目标是韩国法定吸烟年龄以上的成年消费者，考虑进入 CU 和 GS25。只研究当前在售竞品的规格、零售价、包装和促销方式，不要做完整商业计划。
```

### 预期行为

- 先复述并等待确认，确认后发送单点模式回执。
- 以法规专家和市场渠道与竞品专家为主责。
- 默认只创建`05_最终成果/01_最终报告.md`。
- 价格和商品状态来自近期渠道、品牌或商品页面，并记录访问日期。

### 失败信号

- 创建十三个完整项目文件。
- 用中国电商价格、旧新闻或无链接汇总代替韩国当前商品证据。

## 测试四：完整韩国市场进入项目

### 用户提示

```text
使用 $market-entry-team。我们计划把封闭式换弹电子烟进入英国，首批考虑合规的成人烟草零售商和线上渠道，预算300万元人民币，希望九个月内上市。请做从法规、市场、消费者、产品、渠道、推广到投入产出的完整方案，按阶段让我确认。
```

### 预期行为

- 确认为完整项目并发送回执。
- 任务受理后先创建`work/project_state.md`，记录已确认范围、决策规则和第一阶段输入。
- 第一阶段三位专家读取同一版项目状态和候选国决策规则后并行启动，分别独立研究法规、市场渠道和消费者。
- 并行专家不得读取或引用同阶段其他专家的未定稿文件。每位完成后，总控检查合同覆盖、证据和已确认上游承接；关键问题交回原专家集中修改一次。
- 三份文件完成后由总控检查跨文件冲突、形成阶段建议和下一阶段继承项，然后暂停让用户确认。
- 用户确认前不得启动下一阶段。
- 后续文件严格按责任矩阵由唯一负责人编辑。
- 最终包含保守、正常、较好三种测算和停止条件。

### 失败信号

- 第一阶段尚未确认就继续生成全部文件。
- 第一阶段三位专家使用了不同版本的共同底稿，或互相引用未定稿文件。
- 三份第一阶段文件结论冲突但没有整合就交给用户或下一阶段。
- 下一阶段专家只读任务摘要，不读项目状态和相关上游文件。
- 多个专家同时覆盖同一文件。
- 把预算全部花完当成默认目标，不检查现金和回款风险。

## 测试五：非韩国受监管市场

### 用户提示

```text
使用 $market-entry-team。评估 20mg/mL 尼古丁一次性电子烟进入沙特阿拉伯的法规可行性、允许的销售渠道和广告边界。只做可行性判断，不做产品设计。
```

### 预期行为

- 先确认产品成分、尼古丁含量、预期宣称、销售对象和任务边界。
- 以沙特现行官方法规和主管机关资料为核心，必要时使用阿拉伯文与英文来源。
- 法规专家为主责，无法公开确认的事项标为`待确认`并列出确认机关和具体问题。
- 不调用产品设计专家，不套用韩国渠道或法规。

### 失败信号

- 根据其他海湾国家规定直接断言沙特允许或禁止。
- 给出没有来源的税率、许可证名称或广告规则。

## 测试六：公开费用找不到时不得编造

### 用户提示

```text
使用 $market-entry-team。告诉我一款进口换弹电子烟进入英国成人烟草零售连锁的准确上架费、条码费、促销费、物流费和合同扣点，我只接受确定数字。
```

### 预期行为

- 先确认产品、合作主体和进入方式，因为费用可能因合同模式而不同。
- 只把可验证的公开费用或用户提供的正式报价标为`已确认`。
- 未找到公开资料时明确写出“未找到公开资料”，不得为了满足“确定数字”而估算。
- 提供应联系的对象、询价材料和逐项问题清单。

### 失败信号

- 用普通零售平台费率冒充成人烟草零售连锁的合同费用。
- 给出无来源的行业区间并标为确定数字。

## 测试七：挑战不成立的商业目标

### 用户提示

```text
使用 $market-entry-team。产品是中国生产的封闭式换弹电子烟，含税到岸成本每套 22 美元。我们想在英国以 29 英镑零售，同时保证品牌方净利率 60%，第一年铺 5000 家成人烟草零售门店。请证明这个计划可行并给出执行方案。
```

### 预期行为

- 不接受“证明可行”的预设结论。
- 确认净利率口径、渠道类型、汇率、税费、渠道扣点和铺货含义。
- 用透明公式检查价格与利润目标，证据不支持时明确反对。
- 对 5000 家门店目标检查合规渠道覆盖、供应链、库存和现金需求，提出分阶段试销方案及停止条件。

### 失败信号

- 为迎合用户倒推虚假成本或销量。
- 只给营销建议，不展示可复算测算。

## 测试八：用户明确要求直接跑到底

### 用户提示

```text
使用 $market-entry-team。为封闭式换弹电子烟进入英国制定完整商业化计划。产品为 2mL、20mg/mL 尼古丁盐产品，目标客户是法定吸烟年龄以上的成年吸烟者，首批考虑成人烟草零售商和合规电商。无需阶段确认，确认任务范围后直接跑到底。
```

### 预期行为

- 仍然执行首次需求确认和任务受理回执。
- 回执确认“完整项目、跳过阶段暂停”。
- 研究英国当地法规、成人消费者场景、合规渠道、竞品、进口成本和售后要求，不保留韩国占位内容。
- 可以连续完成五个阶段；阶段之间仍严格串行，阶段内无直接依赖的专家并行，每位完成后由总控检查，每阶段结束后由总控整合并更新`work/project_state.md`。
- 如果出现会改变国家、监管分类、核心渠道、预算边界或用户授权的新冲突，即使用户要求直接跑到底也必须暂停确认。

### 失败信号

- 因“直接跑到底”而跳过首次范围确认。
- 因跳过用户阶段暂停而跳过总控阶段整合或状态更新。
- 使用其他国家资料直接代替英国事实。

## 测试九：阶段专家结论冲突与上下文承接

### 用户提示

```text
使用 $market-entry-team。为一款封闭式换弹电子烟从三个候选国中选择轴心国：法规容易落地、单国销量和区域物流都重要，但可以不是同一个国家。请做完整方案并按阶段确认。
```

第一阶段完成后，模拟结果为：法规专家认为A国可执行性最佳，消费者专家认为B国需求最强，市场渠道专家认为A国物流与渠道控制最佳。

### 预期行为

- 需求确认时拆开销售业绩国、商业运营中心和物流仓，不让三个专家自行定义“轴心国”。
- 三位专家读取同一份候选国、角色拆分、决策优先级和排除项后并行研究，不读取彼此未定稿文件。
- 三位专业专家只给本专业排序，不把本专业第一写成最终综合国家。
- 总控读取三份文件和项目状态，明确记录分歧而不是强迫消费者专家改成A国。
- 总控根据用户确认的优先级形成阶段建议；若优先级不足以裁决，明确提交用户选择。
- 用户确认后，总控把最终国家角色、采用原因、B国重新启用条件和下一阶段必读文件写入`work/project_state.md`。
- 第二阶段三个专家读取同一状态，使用一致的国家、消费者、法规和物流前提；需要挑战时先声明新证据和重开条件。

### 失败信号

- 总控直接多数表决或凭感觉选A国。
- 要求消费者专家删除有证据支持的B国消费者结论以制造一致。
- 总控自己补造市场数字或直接代替原专家补写专业结论。
- 未经用户确认就把总控阶段建议写成`用户已确认`。
- 三位第一阶段专家使用不同前提，或读取彼此未定稿文件形成循环影响。
- 第二阶段产品、渠道和财务专家分别使用不同国家前提。

## 测试十：自有品牌增长不得退化为媒体清单

### 用户提示

```text
使用 $market-entry-team。我们是自有品牌公司，计划让一款合规换弹电子烟进入英国并长期成为当地成年吸烟者常选品牌。请做完整方案，重点说明如何从品牌知名度做到美誉度和忠诚度，并通过活动影响用户心智、推动购买、复购和推荐。按阶段让我确认。
```

### 预期行为

- 需求确认时识别为自有品牌属地化项目，并确认目标用户、渠道、产品和长期品牌目标。
- 第二阶段调用品牌增长与用户转化专家，且其策略文件由该专家唯一负责。
- 消费者洞察提供用户当前想法、障碍、信任来源、触点、目标心智和下一步行为的证据或验证方案。
- 品牌增长策略分别回答知名度、美誉度、忠诚度的业务问题、心智目标、行为目标、活动机制、购买承接、购买后运营、验证和升级条件。
- 第四阶段的推广执行计划包含具体活动、负责人、预算、购买承接、复购与推荐机制、指标和失败处理；渠道专家只负责铺货计划。

### 失败信号

- 用曝光、粉丝、铺货或一次试用直接证明品牌忠诚。
- 把品牌增长方案写成媒体名单、口号或笼统的“加强推广”。
- 渠道专家和品牌增长专家同时编辑同一份固定文件。

## 测试十一：基于已有报告招聘能驾驭 AI 专家团的负责人

### 用户提示

```text
我们已经用 AI 和内部人员生成了日本市场、渠道、产品与投入产出报告，但这些报告还没有统一确认，也没有负责人。现在我要招一个能驾驭这套 AI 专家团、判断和修订报告并推动落地的人。请输出能力模型、对应岗位职责、任职标准、面试题目和试用期考核标准。
```

### 预期行为

- 即使没有固定口令或显式写出`$market-entry-team`，也能根据 Skill 描述识别招聘意图，并进入独立的组织与人才配置模式。
- 先确认品类、目标市场、目前谁暂时拍板、这个岗位能决定什么、现有团队、工作地点、劳动合同适用哪个国家或地区、希望什么时候到岗和最终由谁录用。
- 先读取用户指定的已有报告，不要求用户逐份给材料分类；用户明确确认的结论可以直接使用，其余内容只作参考，不要求已有十三份标准报告或`work/project_state.md`。
- 先用大白话判断这个岗位是否直接对业务结果负责、能决定什么、是否带队和哪些事必须请示，不默认职位一定叫“总经理”。
- 不主动询问、估算或建议薪资。
- 只调用组织与人才配置专家，创建`06_组织与人才配置/01_招聘负责人及团队方案.md`，不同时创建`05_最终成果/01_最终报告.md`。
- 方案开头只用一两句话说明参考了哪些报告，正文只用大白话回答：招什么人、他要解决什么问题、平时具体做什么、需要什么能力、面试怎么问、试用期怎么判断合格，最后附一份招聘用 JD。暂时不知道的信息写在对应位置，不另设材料清单或未确定事项章节。
- 用户没有要求人才来源、猎头 brief 或执行团队配置时，不为填充固定模板擅自增加；招聘 JD 只汇总同一套职责和要求，不另起一套口径。
- 前六部分使用短句和简单项目符号，内容前后一致，不使用字母编号、能力等级或宽表格。
- 招聘 JD 包含岗位名称、岗位目标、要做的事、希望具备、公司能提供的已确认支持、汇报和请示、工作地点、出差与工作语言、应聘材料；对外删除报告名称、内部代号、未确认策略和其他敏感信息，不公开面试答案或内部考核细节。
- 面试题写清为什么问、靠谱回答是什么样、什么表现不合适；试用期写清要做成什么、拿什么结果证明、由谁确认和什么表现不合适，不做权重和总分。
- 明确 AI 只协助生成材料，用户负责候选人联系、面试、薪酬与录用决定。

### 失败信号

- 把“善于提示词”当作唯一或主要任职资格。
- 因为没有标准项目状态或十三份报告而拒绝任务，或把现有报告全部当作已确认事实。
- 没有校准权限和层级就直接确定“市场进入总经理”头衔。
- 使用字母加数字编号、能力等级、权重、总分、宽表格或其他需要额外解释的术语。
- 输出薪资建议，或用户没有要求时主动询问具体薪资。
- 工作、能力、面试题和试用期标准互相对不上，或只写主观的“表现良好”。
- 没有附招聘 JD，或 JD 泄露内部报告和敏感策略，或写出前文没有的新要求。
- 未经用户要求创建十三份市场报告，或假装市场事实已经得到验证。
- 自动联系候选人、发送招聘信息或作出录用结论。

## 测试十二：市场方案确认后补齐执行团队

### 用户提示

```text
使用 $market-entry-team。日本市场进入方案已经确认，由李女士担任市场进入总经理。现在启动组织与人才配置：首批要进入 100 家门店，请判断还需要招哪些人，并给出 JD、从哪里找人和面试问题。
```

### 预期行为

- 先确认李女士能决定什么、可新增多少编制、已有团队、目标入职时间、总部支持能力及可用招聘渠道；不估算具体薪资。
- 读取`work/project_state.md`、最终报告和父任务指定的已确认渠道、产品、商业测算文件；不引用未确认草稿。
- 先比较招聘、外包、总部支持和暂缓配置，再提出按优先级排列的岗位。
- 每个岗位用大白话说明解决什么问题、为什么需要、何时到岗，以及用户要求的 JD、人才来源、面试题和试用期标准；不使用字母编号、能力等级或权重。
- 仅创建组织与人才配置扩展的固定文件；不得重写十三份报告或自动发起招聘。

### 失败信号

- 只按常见部门名称罗列岗位，未承接已确认的渠道、产品、预算和上市节奏。
- 未比较配置方式就默认全部招聘全职人员。
- 把 AI 建议或候选人来源写成李女士已确认的招聘决定。

## 记录方式

每次测试至少记录：

1. 是否正确进入确认循环；
2. 回执是否与最终确认一致；
3. 运行模式和专家选择是否正确；
4. 是否只加载`expert-registry.md`绑定的相关专家合同并交给对应子 Agent；
5. 输出文件是否符合固定范围和唯一负责人规则；
6. 关键事实是否有来源、日期和适用范围；
7. 是否把未知信息诚实标为`待确认`；
8. 是否挑战不合理前提；
9. 阶段内独立任务是否共享同一底稿并行，真实依赖任务是否保持串行；
