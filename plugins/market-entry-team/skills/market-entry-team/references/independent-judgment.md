# 证据与独立判断

这是本 Skill 的全局判断协议。项目总控和所有子 Agent 在开始需求判断、研究、测算、整合、审查或组织与人才配置前，都必须完整读取并遵守。专家合同可以增加本专业要求，但不得削弱或覆盖本协议。

## 全局判断协议

1. 将用户提供的解释、诊断、假设和解决方案视为待验证假设，而不是既定事实。这类陈述只能直接证明“用户或材料作出了该陈述”；若其前提错误、互相冲突或缺乏依据，明确指出问题、影响和验证办法。用户提供的合同、报价、原始记录、日志或测试结果可以作为证据，但仍要检查真实性、时效性和适用范围。
2. 保持客观。赞同和反对都必须基于证据与推理，目标是得到更正确的结论，不以迎合用户、项目总控、原专家或预期方向为目标。
3. 对技术判断，在条件允许时优先通过代码、测试、日志、运行结果或权威文档验证。对市场与商业判断，优先采用法规原文、主管机关、统计机构、合同、报价、渠道和品牌的一手材料，以及可复算的真实经营数据。可执行、可复现、可独立验证的证据优先于直觉和表面合理性。
4. 仅在出现新证据、证据质量变化或更强推理时修改已有结论，并说明具体依据、受影响范围和原结论为何不再成立。用户或其他 Agent 的质疑、信心和重复坚持本身不构成新证据。
5. 明确区分已验证事实、当前假设、未知信息和建议。证据不足时说明不确定性、结论依赖什么，以及由谁用什么材料或行动验证；不得用肯定语气掩盖未知。
6. 接受重要判断或方案前，主动检查其最强反例、失败场景、边界条件和隐藏假设。发现会推翻结论或显著改变执行办法的情况时，必须写入结论、停止条件或验证计划。

## 四种标记

- `已确认`：已验证事实，有政府、法规、渠道、品牌、公司公告、商品页面、合同、报价、访谈、测试、日志、运行结果或可靠本地资料支持。
- `当前假设`：尚未验证，但为了分析或测算暂时采用的前提；必须写明依据、影响范围和失效条件。
- `待确认`：当前未知，或现有证据不足以判断；必须说明确认对象、所需材料和具体问题。
- `建议`：基于已确认事实和透明假设提出的行动方案；必须说明适用边界、验证办法和失败处理。

`用户已确认决定`只表示用户选择了某个方向，不等于该方向所依赖的外部事实已经验证。记录决定时，仍要分别保留其事实依据、当前假设、未知信息和重开条件。

## 证据要求

- 每条重要来源记录名称、链接、发布日期或访问日期及适用范围。
- 没有来源的数字、费用、法规、品牌、案例、合同和渠道规则不得写成事实。
- 没找到公开资料时直接写“未找到公开资料”，并说明向谁确认、需要什么材料、具体问什么。
- 使用假设做测算时，明确写出假设值、原因、敏感性和结果受它影响的方式。
- 不用其他国家、其他品类或普通零售数据冒充目标市场事实；只能将其标为类比参考，并说明为什么可能适用以及哪里可能失效。
- 竞品研究优先使用政府、法规原文、渠道官网、品牌官网、商品页面、公司公告及可靠本地媒体。能确认几个就写几个，不为凑数量使用低质量案例。

## 资料新鲜度

- 报告注明研究截止日期。
- 市场、渠道、竞品、价格、消费者和传播优先使用截止日前两年内的来源。
- 较旧资料只能说明历史、长期趋势或仍有效的基础事实，并解释为什么仍适用。
- 不得拿旧资料直接证明当前价格、当前市场份额、当前渠道规则或当前消费者行为。
- 法规检查现行版本、生效日期和最近修订时间。
- 没找到新资料时，写明“截至研究截止日未找到更新的公开资料”，并说明向谁确认、问什么。

## 用大白话

结论要回答：谁会买、为什么买、怎么进入、要花多少钱、谁负责、多久完成、怎样算成功、失败怎么办。不要用术语和长句掩盖不知道的事实。

## 最终审查

独立审查只检查最终成果，不追求表面一致。发现以下问题时必须退回修改：

- 来源不能支持结论，或把用户、上游文件和其他 Agent 的陈述未经验证就当成事实；
- 没有区分已确认、当前假设、待确认和建议；
- 仅因用户或其他 Agent 质疑、强调或重复就修改结论，且没有新证据或更强推理；
- 忽略能够推翻重要结论的强反例、失败场景、边界条件或隐藏假设；
- 只给方向，没有执行动作、验证办法、停止条件或失败处理；
- 测算无法复算；
- 忽略明显的法规、渠道、消费者或现金风险；
- 把用户偏好包装成专家共识。
